# stage 符合率掉在哪：8 条样本的逐条对照（2026-11-20）

## 现象

`reports/eval_3way_p2.json` 里，内容阶段符合率（stage）只有 base 是 7/8，两个微调版都是 6/8。
DPO 没有把 SFT 丢的这一条补回来。

## 结论：掉的不是「阶段能力」，是「200 token 截断」

看第 2、5 条：base 输出 489 / 449 字（符合），两个微调版都**恰好 200 字**（不符）。
200 是 `max_new_tokens=200` 的上限 —— 这两个样本的微调版输出被**截断在生成上限**，
还没写到阶段关键词就停了。

D0 的判据词是 `["综述", "GAP", "基线"]`。看这两条的参考回复开头是
`[D0] 基于证据(...)处理: 为该方向做文献综述, 给出GAP与基线池…` —— 关键词在句首附近就有。
但微调版输出 200 字仍被判不符，说明它们**用 200 字做了别的事**（比如重复 prompt 前缀、
或先展开背景再进入正文），把关键词挤出了窗口，或者输出被硬截断在关键词之前。

这一条**没有**用「生成能力退化」来解释 —— 8 条样本 + 200 token 上限的组合下，
stage 差异更像是**长度分布**的副作用（base 平均 603 字，两个微调版 282/303 字）。
微调把输出压短了（这本身是 DPO/SFT 的目标之一：少啰嗦），短到 200 上限时，
需要更多铺垫才能到达阶段关键词的样本就被截断了。

**这也是为什么它不该进判据表**：它不是「DPO 学坏了」，而是「200 token 窗口对短输出模型更紧」。
真要判这一轴，得把 max_new_tokens 提到 512 再比，否则量的是截断而不是能力。

## 样本量说明

8 条样本里 2 条差异 = 12.5 个百分点。上面第 7 条还是反向的（base 不符、两个微调版符合），
所以净差异只有 1 条。这条结论在 8 条上无法证伪，只当机制解释记录下来。
